# آرکان CRM — سیستم مدیریت ارتباط با مشتری با هوش مصنوعی

CRM کامل و فارسی (RTL) برای شرکت مشاوره‌ی کسب‌وکار «آرکان»، **فاز ۴** پروژه‌ی آموزشی دوره‌ی هوش مصنوعی. این ریپو کل اپلیکیشن را دارد: وب‌سایت، چت‌بات RAG، بلاگ و CRM با پروپوزال و قرارداد. مستندات بر CRM تمرکز دارد.

- **نسخه‌ی زنده:** [arkan-website-chatbot.vercel.app](https://arkan-website-chatbot.vercel.app) (پنل `/admin` رمز دارد)
- **کد همین ریپو** بایت‌به‌بایت همان کدی است که روی نسخه‌ی زنده اجرا می‌شود.

## چرا این معماری؟

CRM بر پایه‌ی **جریان کلاسیک صنعت** (الگوی Salesforce/HubSpot) طراحی شده:

```
لید (صف ورودی)  ──تبدیل──▶  مخاطب + شرکت + معامله  ──پایپ‌لاین──▶  پروپوزال ──▶ قرارداد ──▶ برد
     ▲                              │
فرم سایت / چت‌بات            فعالیت‌ها، کمپین، تایم‌لاین ۳۶۰°
```

- **لید** خام است و از دو کانال خودکار پر می‌شود: فرم مشاوره‌ی سایت و تولِ `capture_lead` چت‌بات.
- «تبدیل» لید، **مخاطب** (شخص)، **شرکت** (سازمان) و در صورت انتخاب یک **معامله** می‌سازد. لید با `converted_at` علامت می‌خورد تا صف ورودی تمیز بماند.
- همه‌چیز حول مخاطب جمع می‌شود: **نمای ۳۶۰ درجه** یعنی تایم‌لاین یکپارچه‌ی لید، گفتگوی چت‌بات، فعالیت‌ها و تغییر مراحل معامله.

### ✨ هوش مصنوعی (همه با OpenRouter؛ مدل از پنل قابل تعویض)
1. **امتیازدهی لید:** نمره‌ی ۰ تا ۱۰۰ با توضیح فارسی؛ خروجی ساخت‌یافته با zod.
2. **خلاصه‌ی گفتگوی چت‌بات** در پرونده‌ی مخاطب: نیازها، دغدغه‌ها، سیگنال خرید.
3. **پیشنهاد اقدام بعدی** برای هر معامله بر اساس مرحله، مدت توقف و فعالیت‌های اخیر.
4. **بازنویسی قرارداد** متناسب با چالش و شناخت مشتری.
5. **ایمیل کمپین شخصی** برای هر گیرنده؛ ادمین قبل از ارسال بازبینی می‌کند.
6. **پیام پیگیری قرارداد** وقتی کلاینت دیده ولی تأیید نکرده.
7. **پیشنهاد محتوا:** مرتبط‌ترین پست بلاگ (فاز ۳) برای پرورش هر لید.
8. **چت با CRM:** مدل با ۴ ابزار پرس‌وجو از Supabase جواب می‌گیرد؛ همان الگوی `capture_lead` چت‌بات در جهت عکس.

> 💡 مدل‌های reasoning (مثل Gemini Flash) بخشی از `maxOutputTokens` را صرف استدلال می‌کنند؛ سقف کم یعنی JSON نیمه‌کاره. برای همین سقف توابع AI بالای ۲۰۰۰ است و صفحه‌هایی که اکشن AI دارند `maxDuration = 60` دارند (`src/lib/crm/ai.ts`).

### 📄 پروپوزال ← قرارداد
```
پروپوزال (قالب خدمت) ─ذخیره─▶ PDF در مرورگر ─ایمیل─▶ کلاینت: انتخاب بسته + تأیید / درخواست تغییر
        ▲ بازنگری (نسخه‌ی ۲، ۳…)                              │
        └──────────── درخواست تغییر ◀─────────────────────────┤
                                                              ▼ تأیید
قرارداد (۱۳ ماده، پیش‌پر از پروپوزال) ─PDF + ایمیل─▶ کلاینت: تأیید آنلاین ─▶ نسخه‌ی تأییدشده برای طرفین
```
- **PDF در مرورگر ساخته می‌شود** (jsPDF + html2canvas-pro): از هر صفحه‌ی A4 تصویر گرفته می‌شود، پس فارسی دقیقاً همان چیزی است که روی صفحه می‌بینید. هزینه‌اش: متن PDF قابل جست‌وجو نیست.
- **صفحه‌بند «اول اندازه بگیر، بعد بچین»:** هر بخش سند یک بلوک است؛ بلوک‌ها بیرون از دید اندازه‌گیری و بعد در صفحه‌ها چیده می‌شوند. تیتر به بلوک بعدی می‌چسبد و فهرست بلند بین صفحه‌ها می‌شکند.
- **ارکستریتور کد است:** ذخیره ← چیدن دوباره با شماره‌ی واقعی ← `onReady` ← PDF ← سرور‌اکشن ارسال.
- **لینک توکن‌دار به‌جای لاگین کلاینت:** یک uuid غیرقابل‌حدس، کلید دسترسی کلاینت است. تأیید قرارداد دو مرحله دارد تا زمانِ چاپ‌شده روی PDF همان زمان ثبت‌شده در دیتابیس باشد.
- ارسال پروپوزالِ وصل به معامله، معامله را به مرحله‌ی «ارسال پروپوزال» می‌برد. پروپوزال دستی هنگام تبدیل، مخاطب و شرکتش را در CRM می‌سازد.

### 💬 چت‌بات (فاز ۲+۳)
پیکربندی مدل به‌ازای هر کانال (وب، ویجت، تلگرام)، سقف نرخ پایدار در دیتابیس، تحویل به انسان، سؤال‌های بی‌پاسخ، خلاصه‌ی خودکار گفتگو، محافظ تزریق پرامپت و ساعات کاری. جزئیات در پیوست «وضعیت پیاده‌سازی» پرامپت چت‌بات.

### 🔐 احراز هویت چندکاربره
- جدول `admin_users` با هش رمز **scrypt** از `node:crypto` (بدون کتابخانه‌ی اضافه).
- کوکی نشست: payload امضاشده با HMAC-SHA256 شامل `{uid, email, role, exp}`؛ مسیر کوکی `/admin` است.
- ۵ نقش: `owner > admin > editor > operator > viewer`؛ بیننده در کل پنل فقط‌خواندنی است.
- **مسیر مهاجرت نرم:** تا وقتی کاربری ساخته نشده، `ADMIN_PASSWORD` کار می‌کند و فرم «ایجاد اولین مالک» در دسترس است. این منطق fail-closed است تا خطای دیتابیس مسیر قدیمی را دوباره باز نکند.
- **audit log نوع‌دار:** هر عملیات مهم با نام کاربر ثبت می‌شود؛ عملیات بدون لیبل فارسی در `src/lib/audit-actions.ts` خطای کامپایل می‌دهد.

> ⚠️ **نکته‌ی امنیتی آموزشی:** نشست‌ها stateless هستند (۳۰ روز). غیرفعال‌کردن کاربر روی کوکی‌های صادرشده‌ی قبلی اثر ندارد؛ ابطال فوری یعنی چرخش `ADMIN_SESSION_SECRET`.

## راه‌اندازی از صفر

### ۱. کد و وابستگی‌ها
```bash
git clone https://github.com/rezaei-sjavad/arkan-crm.git
cd arkan-crm
npm install
cp .env.local.example .env.local
```

### ۲. حساب‌ها و کلیدها
| سرویس | برای چه | ضروری؟ |
|---|---|---|
| [Supabase](https://supabase.com) | دیتابیس | بله |
| [OpenRouter](https://openrouter.ai) | همه‌ی مدل‌های زبانی | بله |
| [Cohere](https://cohere.com) | embedding چت‌بات | بله |
| [Resend](https://resend.com) | ایمیل کمپین، پروپوزال و قرارداد | خیر |
| ربات تلگرام | کانال تلگرام چت‌بات | خیر |

کلیدها را در `.env.local` بگذارید. توضیح هر متغیر داخل خود [`.env.local.example`](.env.local.example) آمده است.

### ۳. دیتابیس
همه‌ی جدول‌ها در اسکیمای **`arkan`** هستند، نه `public`؛ تا روی یک Supabase مشترک با پروژه‌های دیگر تداخل نکنند. در SQL Editor سوپابیس این فایل‌ها را **به همین ترتیب** اجرا کنید:

1. [`supabase/00-arkan-schema.sql`](supabase/00-arkan-schema.sql): ساخت اسکیما و دسترسی `service_role`
2. [`supabase/schema.sql`](supabase/schema.sql): جدول `leads` (فاز ۱)
3. [`supabase/chatbot-schema.sql`](supabase/chatbot-schema.sql): pgvector، جدول‌های چت‌بات و تابع `match_chunks`
4. [`supabase/widget-schema.sql`](supabase/widget-schema.sql): پیکربندی ویجت
5. [`supabase/crm-schema.sql`](supabase/crm-schema.sql): شرکت‌ها، مخاطبان، مراحل، معاملات، فعالیت‌ها، کاربران و audit
6. [`supabase/contracts-schema.sql`](supabase/contracts-schema.sql): قراردادها
7. [`supabase/campaigns-schema.sql`](supabase/campaigns-schema.sql): کمپین‌ها
8. [`supabase/chatbot-upgrade.sql`](supabase/chatbot-upgrade.sql): تنظیمات چت‌بات، سؤال‌های بی‌پاسخ، سقف نرخ، تحویل به انسان
9. [`supabase/proposals-schema.sql`](supabase/proposals-schema.sql): پروپوزال‌ها و ستون‌های تازه‌ی قرارداد

بعد در داشبورد Supabase: **Project Settings → Data API → Exposed schemas** را باز کنید، `arkan` را اضافه و ذخیره کنید. بدون این کار API جدول‌ها را نمی‌بیند.

### ۴. اجرا و اولین ورود
```bash
npm run dev          # http://localhost:3000
```
به `/admin/login` بروید و با `ADMIN_PASSWORD` وارد شوید، یا «ایجاد اولین حساب مالک» را بزنید (رمز فعلی = کد راه‌اندازی). از آن به بعد ورود با ایمیل و رمز است و بقیه‌ی کاربران را از تب «کاربران» می‌سازید.

### ۵. پایگاه دانش و داده‌ی نمایشی
```bash
node scripts/ingest-kb.mjs              # ۲۱ سند knowledge-base/ را برای چت‌بات ایندکس می‌کند
node scripts/seed-crm-demo.mjs          # ۱۰ شرکت، ۱۴ مخاطب، ۲۱ معامله، فعالیت‌ها، لیدها، گفتگوی نمونه
node scripts/seed-crm-demo.mjs --clean  # پاک‌سازی داده‌ی نمایشی
```

### ۶. ایمیل (اختیاری)
در Resend یک دامنه یا زیردامنه تأیید کنید و `RESEND_API_KEY`، `RESEND_FROM` و در صورت تمایل `CRM_NOTIFY_EMAIL` را بگذارید. بدون دامنه‌ی تأییدشده، Resend فقط به ایمیل صاحب حساب می‌فرستد. بدون کلید Resend همه‌چیز کار می‌کند جز ارسال ایمیل؛ قرارداد را می‌شود با «ارسال دستی (فقط کپی لینک)» فرستاد.

### ۷. دیپلوی روی Vercel
ریپو را در Vercel ایمپورت کنید، همه‌ی متغیرهای `.env.local` را در **Settings → Environment Variables** بگذارید و Redeploy بزنید؛ متغیر تازه فقط روی دیپلوی بعدی اثر دارد. `next.config.mjs` سقف بدنه‌ی سرور‌اکشن‌ها را روی `4mb` گذاشته تا PDF پیوست جا شود.

## رفع خطاهای رایج

| نشانه | علت | راه‌حل |
|---|---|---|
| `The schema must be one of the following: public, …` | اسکیمای `arkan` در API باز نشده | Exposed schemas در Data API |
| `permission denied for table …` | جدول تازه بدون مجوز `service_role` | `00-arkan-schema.sql` را اجرا کنید، یا `grant all on arkan.<جدول> to service_role;` |
| `relation "public.…" does not exist` | کوئری روی `public` به‌جای `arkan` | در SQL Editor جلوی نام جدول `arkan.` بگذارید |
| «ایمیل کلاینت معتبر نیست» یا ارسال Resend با خطای 403 | دامنه‌ی تأییدنشده، یا «\n» نوشتاری آخر مقدار (از `vercel env pull`) | دامنه را در Resend تأیید کنید و مقدار متغیر را تمیز کنید |
| «حجم فایل PDF بیش از حد مجاز است» | سند خیلی طولانی | متن را کوتاه‌تر کنید؛ PDF تا ۲٫۹ مگابایت فشرده می‌شود |
| پاسخ چت‌بات خالی یا وسط جمله قطع می‌شود | بودجه‌ی توکن صرف reasoning شده | `max_tokens` را در `/admin/models` حداقل ۲۰۰۰ بگذارید |
| صفحه‌ی بلاگ خالی است | کلیدهای `BLOG_SUPABASE_*` تنظیم نشده | اختیاری است؛ با ریپوی `arkan-blog-agents` پر می‌شود |

## سناریوی دموی کلاس (۱۵ دقیقه)

1. **لیدها** → روی یک لید تازه «✨ امتیازدهی با AI» → «تبدیل به مخاطب» با تیک معامله و مبلغ
2. **پرونده‌ی ۳۶۰ درجه** → «تولید خلاصه» روی گفتگوی چت‌بات → «+ فعالیت جدید»
3. **معاملات** → درگ کارت بین ستون‌ها → «✨ اقدام بعدی؟»
4. **پروپوزال‌ها** → «+ پروپوزال جدید» → قالب «استراتژی رشد» → مخاطب را از CRM انتخاب کن → پیش‌نمایش A4 کنار فرم → «دانلود PDF» → «ذخیره و ارسال با ایمیل»
5. لینک پروپوزال را در **تب ناشناس** باز کن (نقش کلاینت) → بسته را انتخاب کن → «تأیید» یا «نکته دارم»
6. در پنل → «تبدیل به قرارداد» → متن ۱۳ ماده‌ای پیش‌پرشده را نشان بده → «ارسال با ایمیل»
7. لینک قرارداد را در تب ناشناس باز کن → «تأیید قرارداد» → نسخه‌ی تأییدشده با نام، زمان و IP در صفحه‌ی امضا
8. **کمپین‌ها** → سگمنت «لیدهای پیگیری‌نشده» → «تولید همه با AI» → ویرایش یکی
9. **✨ دستیار** → «کدام معاملات بیش از ۱۰ روز مانده‌اند؟» → توضیح tool-calling
10. **گزارش‌ها** و **کاربران / audit log** برای جمع‌بندی
